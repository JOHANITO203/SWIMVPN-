# Repo Cleanup Audit - 2026-05-22

## Scope

Audit only. No files were deleted in this pass.

The goal is to identify generated, local, or historical QA files that may be safe to remove later after owner validation.

## Current Git State Observations

- `dist/` is ignored and generated by the landing build.
- `node_modules/` is ignored dependency install output.
- `.idea/workspace.xml` is ignored local IDE state.
- `screenshots/` contains many tracked QA artifacts and XML dumps from Android visual testing.

## Safe Local Cleanup Candidates

These should generally not be committed and can be removed locally when disk/memory pressure matters:

- `dist/`
- root `node_modules/`
- backend `node_modules/` if present
- `.idea/workspace.xml`

## Needs Owner Validation Before Deletion

### `screenshots/`

The directory contains tracked screenshots and XML dumps used during Android QA:

- dock/metaball iterations,
- orb experiments,
- subscription/server/home QA captures,
- light/dark theme captures,
- window XML dumps.

Recommendation:

1. Keep the most recent accepted QA captures for each major screen.
2. Move long-term visual references into a smaller `docs/qa-snapshots/` folder if needed.
3. Delete failed experiment captures only after the user confirms they are no longer useful.

## Do Not Purge Automatically

- `docs/` files: many contain architecture, token, and historical product decisions.
- Android launcher/notification assets: tied to app identity and platform behavior.
- Payment assets in `public/payments/`: used by the landing.
- `public/brand/`: used by SEO/social/PWA metadata.
- Backend migrations: never delete without a migration policy.

## Suggested Follow-up Command Set

Run only after validation:

```powershell
Remove-Item -Recurse -Force dist
Remove-Item -Recurse -Force node_modules
```

Tracked QA file cleanup should be done with explicit file lists, not wildcard deletion.
