## 3. Programme d'affiliation SWIMVPN (reco)
Normes secteur (sourcé [wecantrack](https://wecantrack.com/insights/vpn-affiliate-programs/), [getlasso](https://getlasso.co/niche/vpn/)) : CPA $13–36/vente ou rev-share 30–100 % 1ère vente + 15–35 % récurrent ; cookies 30–90 j ; outils in-house ou Impact/CJ/Post Affiliate Pro ; min payout ~$100.
**Reco simple, alignée sur tes rails (SwimPay + crypto)** :
- **Modèle** : **30 % de revenu récurrent à vie** par client (pas de gimmick 100 %-1er-mois → le récurrent récompense les relations admins/créateurs et inspire confiance à l'audience privacy, comme le 30 %-lifetime de ProtonVPN).
- **Attribution** : **code promo/coupon par affilié** en mécanisme primaire (marche même sans cookie, et sur les checkouts Telegram/crypto où le cookie est non fiable) + lien tracké cookie 45 j en secondaire.
- **Outils** : **Tapfiliate** ou **FirstPromoter** (attribution par coupon, payout manuel/crypto) plutôt qu'un gros réseau (CJ/Impact = pensés rails carte).
- **Payout** : **crypto (USDT) + manuel**, **min $50**, mensuel, après une courte rétention anti-remboursement → matche tes rails + paie les partenaires diaspora/africains sans infra carte.
- **Termes** : pas d'enchères sur la marque « SWIMVPN » ; divulgation promo obligatoire ; pas de spam/fraude à l'install incentivée ; clause claims honnêtes (pas de « 100 % anonyme »). Intake unique : `affiliate@` ou formulaire public.

## 4. Setup d'envoi email (Resend — déjà en place)
- **Domaine** : tu as un domaine + Resend configuré (`MAILER_FROM_EMAIL=support@swimvpn.pro`). **Reco** : dédier un **sous-domaine d'envoi** (ex. `mail.swimvpn.pro` ou `news.swimvpn.pro`) **distinct** des emails transactionnels critiques, pour isoler la réputation du marketing du sign-up/confirmation.
- **Auth DNS (à vérifier "Verified" côté Resend)** : **SPF** (include Resend), **DKIM** (clés Resend), **DMARC** (`p=quarantine` au lancement, monter vers `p=reject` ; rua pour les rapports). Sans les 3 alignés → spam/rejet.
- **Conformité d'envoi** (cf. [séquence](optin-email-sequence.md)) : n'envoyer qu'aux **CONFIRMED** ; **lien de désinscription dans CHAQUE email** (`{{unsubscribe_url}}` — **endpoint à câbler avant tout broadcast**, cf. backlog) ; identité/adresse expéditeur en pied (CAN-SPAM) ; cadence ≤ 1 / 2-3 j au lancement ; warm-up progressif du sous-domaine (volume croissant) pour la délivrabilité.
- **Déclenchement = geste user/plateforme**, jamais autonome.
